## 1. 总原则 [定]

1. **画布优先**：图纸永远铺满工作区，所有面板浮在图纸上方。不改成固定侧栏。
2. **简约**：少即是多。没用的按钮不出现，低频操作收进 ⋯ 或右键，一屏只有一个主按钮。
3. **不丢能力**：除 §3 明确撤销的，现有功能、数据、快捷键、自定义设置一律保留。被挪走的功能必须写清新的入口。
4. **一个数据只有一个来源**：同一个数（如设备数量）不许在两个地方各存一份。
5. **屏幕和 PDF 一致**：屏幕上看到的断行、位置，导出的 PDF 必须一模一样。
6. **动效服务于功能**：每种动效对应一种含义，不为动而动。
7. **用户的肌肉记忆优先**：现有快捷键默认值不变，用户自定义的键永不被覆盖。

### G-03 窗口外框 [定]

现状：主窗口用系统默认外框（`electron/main.ts:1766-1788` 没有 `frame` / `titleBarStyle`），于是最上面是一条 Windows 白色标题栏，下面是 36px 的模块栏 `.module-rail`，再下面是绘图工具栏，共三层。夜间模式下顶上挂一条白条。

目标：去掉系统标题栏，`.module-rail` 这一行兼作标题栏，三层变两层。

```ts
// electron/main.ts —— 主窗口（启动画面不动）
mainWindow = new BrowserWindow({
  // ……原有参数全部保留……
  titleBarStyle: 'hidden',
  titleBarOverlay: { color: theme.titlebarBg, symbolColor: theme.titlebarInk, height: 40 },
});
// 主题变化时由渲染进程经 preload 通知主进程：
ipcMain.handle('window:set-titlebar-colors', (_e, c: { color: string; symbolColor: string }) =>
  mainWindow?.setTitleBarOverlay({ ...c, height: 40 }));
```

```css
/* 模块栏兼作标题栏 */
.module-rail {
  height: 40px;
  padding-right: calc(100vw - env(titlebar-area-x, 0px) - env(titlebar-area-width, 100vw)); /* 给系统三个按钮留位 */
  -webkit-app-region: drag;                      /* 空白处可拖动、双击最大化、拖到边缘贴靠 */
```

- 布局（左 → 右）：图标 + 字标“胥宇” ｜ 五个模块（G-04） ｜ 弹性空白（可拖动） ｜ 全局进度（有任务时才出现，G-04） ｜ 更新图标（有更新时才出现，原逻辑） ｜ 主题 ｜ 帮助 ｜ 关于 ｜ [系统的 ─ □ ✕]。

- 验收：白天、夜间、护眼下整窗一个颜色，没有白条；拖动、双击最大化、贴靠、拉边缩放都正常；三个系统按钮不被任何控件压住（窗口 900 宽时也一样）。

### G-07 命令与快捷键 [定]

- 唯一注册处：`src/core/keyboard-shortcuts.ts` 的 `SHORTCUT_DEFINITIONS`。工具栏、竖条、菜单、浮窗里的**每个可点击操作**都要有对应的命令 id，DOM 上带 `data-command-id="<id>"`。
- 现有默认键**全部不变**（见 `docs/ui-inventory/00-全局.md` 的快捷键表）。

- “全部命令”（现有快捷工具里已有同名入口，P0 报告其现状），按演示页：

### T-05 换主题的动效 [定]

背景：v3 演示页切主题时内容区横向滑动 12px 并与旧画面交叉淡化，不同风格边框粗细不同，交叉淡化出现重影，用户感觉是“震动”。软件里**不许照搬演示页的做法**。

目标：新主题从用户点击的位置圆形展开铺满，不滑动、不重影。

```ts
export async function switchTheme(apply: () => void, origin: { x: number; y: number }) {
  const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
  if (!document.startViewTransition || reduce) { apply(); return; }
  const r = Math.hypot(Math.max(origin.x, innerWidth - origin.x), Math.max(origin.y, innerHeight - origin.y));
  const transition = document.startViewTransition(apply);
  await transition.ready;
  document.documentElement.animate(
    { clipPath: [`circle(0px at ${origin.x}px ${origin.y}px)`, `circle(${r}px at ${origin.x}px ${origin.y}px)`] },
    { duration: 320, easing: 'cubic-bezier(.2,0,0,1)', pseudoElement: '::view-transition-new(root)' },
  );
}
```

```css
::view-transition-old(root), ::view-transition-new(root) { animation: none; mix-blend-mode: normal; }
```

- 自动切换（日出日落、跟随系统）触发时没有点击点：从标题栏“主题”按钮的位置展开。
- 标题栏系统按钮颜色在 `apply()` 里同步调用 `setTitleBarOverlay`。

### T-07 对比度与语义门槛 [定]

## 6. 动效与反馈（M）

用户的原话是“颜色太单调”“布局交互很垃圾”“希望加一些小巧思，比如摁下去的感觉、页面切换的过渡”“各种反馈都可以做，我只是只知道这一种”。v3 演示页的“反馈与动效目录”（9 类 26 项）就是对这句话的回答，用户看过、没有否定；用户唯一明确不满意的是**切换主题时像在“震动”**，并且说明“不是要求你所有的都要换”。所以：

- 反馈目录**整体沿用**（M-04），代码在 `reference/demo/`（`components.css`、`motion.css`、`feedback.js`），按里面的类名、函数名实现；
- 只改换主题的动效（T-05）。

### M-01 原则：一种动效对应一种含义 [定]

| 场景 | 动效 | 含义 |
|---|---|---|
| 换主题 | 从点击处圆形展开（T-05） | 换装 |
| 切换模块 | 只淡入淡出，不位移（`vt-out` / `vt-in`） | 换了一个地方 |
| 按下按钮 | 按各风格的 `--btn-press-*`（缩小 / 下沉 / 压进投影） | 按下去了 |
| 放置点位、放置汇总图例 | 落点涟漪 `ripple()` + 弹入 `.fx-drop-in` | 落地 |
| 数量变化 | 新数字滑入 `animateNumber()`，需要时带差值气泡“+1” | 数据变了 |
| 出错 | 抖动 + 红框 + 说明 `shake()`；点了不可用的按钮：轻摆 + 说明原因 `explainDisabled()` | 不行，以及为什么 |
| 完成交付（完成并下一份） | [待] 用户还没挑，**保持现状** | |
| 首页卡片出现 | [默] 只淡入，不上浮 | 与“切换只淡入淡出”一致 |

### M-02 时长与属性限制 [定]

动效分三档（与演示页 `tokens.base.css` 的注释一致）：

| 档位 | 是什么 | 时长 | 例子 |
|---|---|---|---|
| **交互** | 对一次操作的直接回应 | ≤ 320ms，用 `--dur-instant 80` / `--dur-fast 120` / `--dur 180` / `--dur-slow 240` / `--dur-emph 320` | 按压、开关、弹出菜单、对话框进出、数字滑入、抖动 |
| **余晖** | 操作完成后留一下的提示，类名都以 `fx-` 开头 | 单次 ≤ 1200ms，必须 `pointer-events: none`、**不挡任何操作** | 行高亮淡出 `fx-flash`（1200）、差值气泡 `fx-delta`（700）、定位脉冲 `fx-locate`（900 × 2）、落点涟漪 `fx-ripple`（480） |
| **持续状态** | 某件事正在进行时的指示 | 可循环，**状态结束立即停** | 转圈、保存中呼吸点、骨架屏扫光、不确定进度条、撤销 Toast 的倒计时条 |

- 不许对布局属性做动画（`width / height / top / left / right / bottom / inset / margin / padding / font-size`），不许 `transition: all`（`diff-guard` G5）。颜色、阴影、透明度、变换、`clip-path`、`filter` 可以。
- “减少动效”（系统设置或软件内开关 `:root[data-motion="reduced"]`）时：交互和余晖立即完成，持续状态改为静态指示（例如转圈变成“…”），功能不变。现有 `styles.css` 末尾的 `prefers-reduced-motion` 规则保留。
- 图纸内容本身不做动画；涟漪、弹入、定位脉冲画在独立的 UI 叠加层上，**不进入导出**。

### M-03 模块切换只淡入淡出 [定]

用 `motion.css` 的 View Transitions 写法（`.app-main { view-transition-name: app-main }` + `vt-out` / `vt-in`，旧页 120ms 淡出、新页 240ms 淡入），顶部导航和状态栏不参与过渡。演示页早期版本带 12px 横移，用户觉得像抖，已经去掉；`--page-shift` 变量不要用。P0 报告软件现在模块切换有没有动画、在哪里。

### M-04 反馈与小巧思目录：用在胥宇的哪里 [定]

“名称”列是 `reference/demo/` 里的类名或函数名，Codex 按名字实现。“用在哪”是本规格指定的落点，每一处都要做到；目录里有、但下表没写落点的，不要自己找地方加。

| 类别 | 效果 | 名称 | 用在哪 | 档位 |
|---|---|---|---|---|
| 触感 | 按下的手感随主题（缩小 / 下沉 / 内凹） | `--btn-press-*`、`.ui-btn` | 所有文字按钮 | 交互 |
| 触感 | 图标按钮按下缩到 0.92 | `.ui-icon-btn:active` | 左侧竖条工具、浮窗标题栏的图钉 / 关闭、缩放胶囊 | 交互 |
| 触感 | 开关按住时拇指压扁拉长，松开弹过去 | `.ui-switch` | 状态栏“吸附”、主题“自动切换”、配置里的开关 | 交互 |
| 触感 | 勾选时 ✓ 被画出来 | `.ui-check` | 工作台新文件、资料整理、队列多选 | 交互 |

### M-05 颜色不再单调 [默]

用户说“颜色太单调”。根因：现在底色、边框、灰字、强调色全是同一个青灰色系，没有色相差别。除了主题风格（T-01）之外：

- 中性色换成暖灰（风格“素”已经是暖灰，见 `themes.generated.css`）；
- 五个模块各有一个识别色（`--mod-desk / files / draw / perf / conf` 的 `-bg` / `-fg`），用在模块栏图标底块和页面标题图标上，当前模块下面的强调条用 `moveIndicator()` 滑动过去；

- 目标：编辑界面改成分段控件“点位设备 ｜ 汇总设备”二选一。
  - 点位设备：在图上逐个放置、自动编号，汇总数量 = 图上点位数。
  - 汇总设备：不在图上打点，只出现在汇总里（录像机、交换机等）。
- 数据格式**不改**（团队配置包要兼容导入导出）：读入时归一成只含一个角色的数组。归一规则（2026-10-12 定，见 `06-P0结论与连续执行.md` 第三节第 1 条）：两个都勾 → 点位设备；都不勾 → 点位设备，并在团队配置里提示 `角色未设置，已按点位设备处理`。

### S-02 数量只存一份 [定]

- 现状（根因）：
  - 托盘行 `EquipmentTrayItem.total` 和图例对象 `EditorObject.quantity` 各存一份。属性栏改的是对象，汇总弹窗改的是托盘行，两边不同步。
  - 冲掉手改的有两条路：
    1. `refreshEquipmentSummary`（`src/core/equipment.ts:213-221`，“设备汇总”按钮 → `generateTray`）把**点位设备**已放置图例的数量改回点位数；
    2. 汇总弹窗“更新并放置”`confirmEquipmentTray`（`App.tsx:3356-3412`，写入在 3388 行）把弹窗里的数（来自托盘行，不是图上的数）写回**所有**已放置图例。用户在属性栏改过的录像机数量就是这样被冲掉的。
- 目标：
  - **托盘行是唯一来源**。新增可选字段 `EquipmentTrayItem.manualTotal?: number` 存手改值；`total` 只表示基准（点位数 / 模板数 / 本图纸添加时的数）。
  - 图例对象的 `quantity` 只是显示副本，由同一个函数写入。
  - 行为样板与测试：`reference/summary-quantity.ts` + `summary-quantity.test.ts`（16 个用例），移植后必须全部通过。

### S-03 数量来源与手改规则 [定]

| 来源标签 | 含义 | 回退按钮 |
|---|---|---|
| 点位 | 图上点位数（点位设备默认） | — |
| 模板 | 方案预设数量（汇总设备默认） | — |
| 添加 | 本图纸“＋ 添加设备”时填的数 | — |
| 手改 | 用户改过 | 点位设备：“改回自动（7）”；汇总设备：“改回模板（1）” |

- **手改值等于基准值时，视为没有手改**，标签自动变回“点位 / 模板”。之后点位数变化，它继续跟着变，不会“看着是 6、其实被钉死在 6”。
- 点位设备手改且与图上点位数不同时，这一行和图上的图例旁都显示琥珀色小标记 `图上 7 · 手改 6`（**编辑器里才有，不进导出**）。
- 预留：`computed`（按规则计算，给以后的录像机自动计算用）只在类型里留位置，本轮**不实现任何计算**（S-13）。

### S-04 改数量的入口 [定]

- 选中汇总图例 → 属性浮窗：数量步进器 + 来源标签 + 回退按钮。
- 汇总清单里每一行也能改。
- 两处改的是同一个托盘行；**改完立即写到图上的图例，原位不动**；改成 0 则移除该图例（同一个撤销步骤）。

### S-05 图例排版：按真实尺寸，永不重叠 [定]

- 现状（根因）：
  - `addAllDevicesFromTray`（`App.tsx:3512-3529`）一行横排，每步只前进“图片宽 + max(18, deviceNameGap + 12)”，从不换行，超出页面就压到页面外。
  - 标签在图片正下方居中，默认宽 = 图片宽 + 40（`src/core/object-label-layout.ts:27-29`）。所以相邻标签至少互相压 ~22px，名字长时压得更多。
  - 再次生成时把新一排的**中心**放在“最后一个图例右边 30”（`App.tsx:3321-3325` 算放置点，`addAllDevicesFromTray` 再减去一半总宽），所以新一排有一半会压回已有图例上。
- 目标：按 `reference/legend-layout.ts` 的规则排版（10 个用例，含 120 组随机形状）：
  - 每个图例的占位 = 图片与标签的并集；图片可以是任意比例（扁长的录像机、竖长的摄像机、细长的交换机都有），**不假设正方形**。
  - 标签最大宽度内自动换行；**“× 2台”永不拆开**；型号优先在连字符后断开，实在放不下才硬拆。
  - 为数量预留 3 位数的宽度和行数：数量从 1 涨到 999，图例占位不变、不会压到邻居。
  - 方向是方案设置“图例排列：横排（默认）/ 竖排”，满了分别换行 / 换列，间距固定。
  - 新图例避开页面上已有的图例、分类说明、文字等对象的占位框。
  - 放不下时照样放，但提示“N 个图例超出页面”。
- 排版结果写回对象：`x / y`、`labelWidth`（固定标签框）、`labelOffset`、`style.align`。
- **标签位置 [待]**：现在软件里文字在图片**下方**居中；演示页里文字在图片**右侧**、左对齐、与图片垂直居中。用户确认前保持下方。参考实现两种都支持（`labelPosition: 'below' | 'right'`），右侧样式不新增字段，用现有 `labelOffset` 实现。
- **同一型号用在两个分类时 [待]**：现在软件合并成一行（`equipment.ts:79-81` 注释写明“设备汇总始终按素材/型号合并”，分类来源显示“跨分类合计”）；演示页分成两行（`D6PS-1（监控）× 6台`、`D6PS-1（客流）× 1台`）。用户确认前保持合并。

### S-06 标签断行只算一次，屏幕与 PDF 一致 [定]

- 现状：同一段标签被换行三次，算法各不相同：
  - 画布：Konva `wrap="char"`，按字符断，用画布字体实测宽度（`FloorPlanCanvas.tsx:1582` 等四处）；
  - PDF：`wrapSelectableText`（`electron/services/pdf-export.ts:304`），按字符断，用 pdf-lib 字体实测宽度；
  - 高度估算：`automaticTextBoxHeight`（`src/core/text-layout.ts`），第三种估算。
  三者断行位置可能不同，“× 2台”也可能被拆开。
- 目标：断行在 `src/core` 里算一次（用 `legend-layout.ts` 的 `wrapLabel`，宽度估算与 `text-layout.ts` 同一公式），得到明确的行；画布用 `wrap="none"` 按行画，PDF 也按这些行画，**两边都不再自行换行**。适用于汇总图例标签；点位编号标签同理（P0 评估影响面后决定是否同批）。

### S-07 放置流程 [定]

1. 点画布空白处 → 记为“放置点”，出现淡淡的十字标记（现有 `pasteTarget`）。
2. 鼠标悬停在“设备汇总”按钮上 → 在放置点画出虚线占位框（每个图例一个），旁边一个小标签 `设备汇总放这里 · Ctrl+Alt+G`；按钮提示 `放置设备汇总（N 项）到你在图上点的位置`。放置点本身一直显示一个淡淡的十字，直到下一次点画布。
3. 点“设备汇总”（Ctrl+Alt+G，原有）→ 从放置点开始排版放置，图例依次落入（`staggerDropIn`），出现撤销型 Toast `已放置设备汇总：N 项 [撤销]`，按钮徽标从数字变成 `✓`。整个过程是一个撤销步骤。
4. 没点过画布 → 放在当前可见区域（两列浮窗之间）的左上部。
5. **之后再点“设备汇总”：已放置的图例一个都不动，只原位更新数量**；新增的设备放到最后一次点画布的位置（标记“新增 2 项放这里”），没点过就放在已有图例旁边（作为障碍物避开）。
6. 拖动：默认**单个**拖动（用户要把各个图例、分类说明分别放到空白处）；**Shift + 拖动**整组（同页全部汇总图例，拖动时显示整组外框）。图例悬停提示 `拖动：单独移动 · Shift + 拖动：整组移动`。
7. 画布上的图例旁边（只在编辑器里，不进导出）按情况挂小标记：`6→7`（待更新）、`3→0 移除`（下次更新会移除）、`图上 6 · 手改 5`（手改不一致，琥珀色）。

### S-08 数量为 0 [定]

- 数量为 0 的设备不进汇总图例。图上已有的，在应用时直接移除（可撤销）。
- 来源：这张图没用到某个点位设备，或用户手动改成 0。

### S-09 待更新提示 [定]

- 点位增减后，已放置图例的数量不会自己变，图例旁挂一个小标记 `6→7`（编辑器里才有，不进导出），提醒点“设备汇总”更新。手改过的行不挂（它不跟点位数）。

### S-10 导出前检查 [定]

- 导出（含批量导出）前，如果有点位设备“手改值 ≠ 图上点位数”，弹窗：
  - 标题：`有 N 项数量与图上点位不一致`
  - 列表：`D6PS-1：图上 7，手改 6`
  - 按钮：`全部改回自动`、`保持手改并导出`（主按钮是后者，Esc = 取消导出）
- 全部一致时不弹任何东西。批量导出时，有不一致的文件在导出记录里标“已按手改导出”。

### S-11 汇总清单（托盘 + 弹窗合并成一个浮窗）[定]

- 现状：“设备汇总弹窗”（`App.tsx:7625-7781`）和可拖动的“设备汇总托盘”（`App.tsx:6161-6260`）是两个东西，用户分不清。
- 目标：合并成右列的一个浮窗“汇总清单”。入口：“设备汇总”按钮旁的 ▾，或 `Ctrl+Alt+H`（G-07）。
  - 标题栏：`汇总清单` + 当前方案名（小字）+ 图钉 + 关闭。演示页标题栏上的“横排 / 竖排”切换只是演示，正式放在方案设置（S-05）。
  - 表头：`设备` ｜ `数量`。
  - 每行：`⠿` 拖动手柄（按住拖到图上任意位置 = 单个放置；拖到已放置的设备 = 给它挪位置；数量为 0 的行没有手柄）｜ 图标 ｜ 名称 + 分类（小字）｜ 数量步进器（按住连发）｜ 来源标签（S-03）｜ 悬停才出现的 `⌖` 定位按钮（画布跳到该图例并脉冲两次，M-04）。
  - 行下附加说明：手改不一致时 `图上 6 个 · 改回自动（6）`（琥珀色，“改回自动”可点）；数量为 0 时 `数量为 0：更新后从图例移除（可撤销）`。
  - 列表下方一行灰字：`拖动左侧 ⠿ 可以把单个设备放到图上任意位置。数量都能手改，改了立即写到图例上；改回和自动值一样时，自动恢复为“跟随自动”。`
  - 底部：`＋ 添加设备`（模板里没挂上的设备在这里补，只加到这份图纸）｜ 状态文字（`图例与数量一致` / `N 项待更新`）｜ 主按钮。
  - 右下主按钮按状态变化：`全部放到图上` → `放上剩余 N 项` → `更新到图上（N）` → `已是最新`（禁用）。规则见 `summary-quantity.ts` 的 `primaryAction`。
- “常用设备组合”（`equipmentPresets`）功能保留，入口在设备浮窗底部（D-13）。

### S-12 分类说明（点位说明）[定]

- 现状：固定生成在页面 (40, 40)（`src/core/descriptions.ts:77-105`），常压在图纸标题上。
- 目标：和设备汇总同一套规则：先点画布，生成在放置点；之后单独拖动。再次生成只更新文字，不移动。
- 顶栏按钮名保持“点位说明”，命令名“生成分类说明”（Ctrl+Alt+D）不变。

### S-13 录像机自动计算：只预留数据 [定]

- 先分清两件事（P0 报告把它们混在了一起）：
  - **按图上点位自动计数**（`src/core/equipment.ts` 的 `equipmentGenerationItems`：每个型号数图上有几个点位，`automatic: true`）——这是 S-02 里数量来源“点位”，**现有逻辑保留**，本条不碰。
  - **录像机 / 交换机按通道数推算**（下面的规则）——现在代码里没有，本条说的就是它。
- 本轮只在数据里留位置，**不做界面、不做计算**：
  - `TeamAsset` 可选：`nvrChannels?: number`、`poePorts?: number`；`needsRecording?: boolean`（摄像机）。
  - 数量来源类型里保留 `computed`。
- 以后的规则（仅供参考，不要实现）：录像机台数 = ⌈需录像摄像机数 ÷ 通道数⌉；PoE 缺口 = PoE 摄像机数 − 录像机台数 × 每台 PoE 口数；有缺口时交换机台数 = ⌈缺口 ÷ 交换机 PoE 口数⌉。

### S-14 旧工程迁移 [定]

- 第一次用新版本打开旧工程时，跑一次 `migrateLegacyQuantities`：**以图上显示的数为准**。和基准不同的记成手改；点位设备的这类差异会被琥珀色标记和导出前检查暴露出来，由用户一键改回自动。迁移本身**不改变图上任何内容**。
- 迁移后的工程写入一个版本标记，避免重复迁移。

   - 可选动作（按需点，不在主列表上摆一排）：`改名`、`品牌前缀`、`归档到历史`、`清理存放文件夹`。
   - `清理存放文件夹` 由现在的永久删除改为**移到回收站**（Electron `shell.trashItem`），同样记进“文件操作计划 + 回退”（2026-10-12 定，06 第三节第 4 条）。

### A-04 预览清晰度 [定]

- 按屏幕真实像素密度渲染（`scale × devicePixelRatio`）；PDF 是矢量的，放大时重新渲染，不拉伸位图，不许糊。
- 默认适配宽度；滚轮放大局部，拖动平移；空格或双击打开大图预览，再按空格关闭。

- 加载中如实显示阶段，失败显示原因和“重试”（协调仓 AGENTS 第 11 条）。

### I-03 修复：全新安装点“开始安装”没反应 [定]

- 现象（Wine 复现）：没有装过胥宇的电脑上，默认路径如 `D:\XUYU` 还不存在，点“开始安装”页面不动，也没有提示。
- 根因：`installer.nsh` 的 `XuyuSetPathFromParent` 用 NSIS 自带的 `GetFullPathName` 规范化路径，它在末级目录不存在时返回空值；离开页面时 `$XuyuChosenInstallDir` 为空，于是 `Abort`。用调试版把值弹出来确认过：`chosen=[] parent=[Z:\XUYU]`。
- 为什么一直没发现：覆盖升级时走“沿用原位置”的分支，不经过这段；自动测试用 `/S /D=`，也不经过这段；点“更改…”选一个已存在的父目录也能绕开。
- **P0 必须在 Windows 真机上全新安装一次确认**（干净用户或虚拟机，默认路径，不点“更改…”）。无论真机是否复现，都按新实现改：用 Win32 `GetFullPathNameW` 只做规范化（不要求目录存在），再检查盘符 / 共享根存在。

### I-21 什么时候用水墨界面 [定]

`installer-inkui.nsh` 的 `XuyuInkUiRun` 按顺序判断，**任何一条不满足就直接走经典向导**（和改版前完全一样，用户看不到报错）：

1. 不是 `/S` 静默安装。应用内更新、`installer-smoke.mjs`、Preview 门禁的 smoke 都是静默的，**永远不会出现水墨界面**。
2. 不是 UAC 提权后的内层进程；命令行没有 `/classic`。
3. 当前是“仅当前用户”，并且本机没有“所有用户”的安装。“给这台电脑的所有用户安装…”要管理员权限，交给经典向导（它有现成的提权流程，进去时“这台电脑的所有用户”已预选）。
4. 64 位 Windows 10 及以上；注册表能找到 WebView2 运行时（`EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` 的 `pv`，先查 HKLM 再查 HKCU，空或 `0.0.0.0` 算没有）。
5. 宿主能解出来、能启动，并在 20 秒内出界面（写 `ready.flag`）。
6. 宿主自己再查一遍：Windows 高对比度模式、WebView2 运行时版本取不到、WebView2 初始化失败、还没做决定时页面进程崩溃 → 写 `decision=classic` 退出。

### I-22 默认安装位置 [定]

用户：“基础逻辑你别忘嗷，要优先装到用户非系统的最大盘。”

- 默认位置**只由 NSIS 原有的 `XuyuChooseDefaultInstallDirectory` 算**（经典向导和水墨界面共用）：本地硬盘里剩余空间最大的**非系统盘** + `\XUYU`；没有非系统盘时用剩余空间最大的盘；一个本地硬盘都没有时用 electron-builder 的默认位置。宿主和页面**不许自己算默认位置**，只显示 `init.ini` 给的 `dir`。（撤销清单 X27）
- 已经装过（当前用户）→ 沿用原位置（`dirSource=previous`：页面写“位置不变”，没有“更改”）；命令行带 `/D=` → 用它（`param`）。
- 路径下面那行说明由 `dirSource` 决定：`auto` → `D: 盘剩余 128 GB · 剩余空间最大的非系统盘`；`auto-system` → `C: 盘剩余 80 GB · 没有其他本地盘`；其他 → 只写剩余空间。
- “更改”打开系统的“选择文件夹”对话框（新样式；标题 `选择安装位置（会在里面建一个 XUYU 文件夹）`，确定按钮 `选这里`）。选的是**父目录**，自动在里面建 `XUYU`；选的文件夹本身就叫 `XUYU`（不分大小写）就不再套一层——和经典向导 `XuyuSetPathFromParent` 同一规则。
- 路径检查（宿主 `PathCheck`，选完、点“安装”时各查一次；不通过就停在欢迎页，路径变胭脂色、那块左右晃一下、下面写原因，文案见 §13）：绝对路径；盘或共享根存在；不是盘的根目录；不在 Windows 文件夹里；剩余空间 ≥ 需要的空间 + 64 MB；最近的已存在上级目录可写（建一个临时文件再删掉，不在用户选的位置留下任何东西）。
- Wine 实测：`init.ini` 里 `dir=Z:\XUYU`、`dirSource=auto`（Wine 的 Z: 盘就是那台机器上剩余空间最大的非系统盘），说明这段逻辑原样传到了水墨界面。

### I-23 宿主与 NSIS 的约定 [定]

会话目录 `%TEMP%\XuyuSetupUI-<安装程序 PID>`：宿主、页面，加上下面几个文件。全部是 **UTF-16LE 带 BOM** 的 INI（`WriteINIStr` / `GetPrivateProfileStringW` 才会按 Unicode 读写，中文路径不会变成问号）；宿主写文件一律先写 `.tmp` 再改名，NSIS 读到的永远是完整文件。

| 文件 | 谁写 | 字段 |
|---|---|---|
| `init.ini` `[init]` | NSIS | `protocol=1`、`nsisPid`、`setupExe`、`version`、`mode=fresh/upgrade`、`installedVersion`、`dir`、`dirSource=auto/auto-system/default/previous/param`、`needKB`、`allUsersAvailable`、`canLaunch` |
| `ready.flag` | 宿主 | 页面已经出来 |
| `decision.ini` `[decision]` | 宿主 | `action=install/cancel/classic`、`dir`、`allUsers`、`reason` |
| `status.ini` `[status]` | NSIS | `phase=prepare/extract/copy/finish/done`、`extractDone`、`extractTotal`（字节）、`launchResult`（只为排查） |
| `after.ini` `[after]` | 宿主 | `action=launch/finish` |

- 时序：`.onInit` → `customInit` 先算默认位置 → `XuyuInkUiRun` 写 `init.ini`、用 `CreateProcessW` 启动宿主并拿到它自己的进程句柄（**不要**换成 ShellExecute / `StdUtils::ExecShellWaitEx`：它们拿到的句柄不一定是宿主本身，Wine 实测会提前“结束”，NSIS 就不等了） → 每 100ms 看一次 `decision.ini`；宿主退出却没留决定 → 经典向导；20 秒没有 `ready.flag` → 结束宿主、经典向导。
- `install`：`$INSTDIR` = `decision.ini` 的 `dir`；`customInit` 里 `SetSilent silent`（SetSilent 只能直接写在 .onInit 里，不能放进被调用的函数），之后**不再出现任何 NSIS 窗口**。`cancel`：退出码 1。`classic`：`allUsers=1` 时经典欢迎页预选“这台电脑的所有用户”。
- 页面 ↔ 宿主的消息（`chrome.webview.postMessage`）列在 `ui/app.js` 文件头。**字段名不许改**；要加字段，三处一起改（`ui/app.js`、`host/XuyuSetupUI.cs`、`installer-inkui.nsh`），`protocol` 加 1，并在报告里说明。

### I-24 界面：水墨 [定]

- 左边是“界画”：一张平面图用毛笔线画在纸上（SVG 滤镜：手拉的轻微起伏 + 纸纹 + 一圈很淡的洇开）；右侧竖排题款 `让方案，清晰呈现。`；纸背透出一个极淡的“宇”。**不加印章**（G-02、撤销清单 X25）。

- 动效（M-02 三档，系统关闭动画或“减少动效”时全部去掉）：
  - 欢迎页第一次出现：墙一笔一笔画出来（≤ 1200ms 余晖，不挡操作，只播一次）；
  - 安装中：一笔横画从左写到右，长度 = 真实进度，笔尖一小段湿、渐淡（不是一刀切）；走到哪，平面图上的摄像机墨点就落到哪（落下 220ms + 洇开 1000ms + 视野淡墨渲开 900ms）；准备阶段没有数字，只在起笔处“蘸墨”（呼吸）；
  - 完成：一笔圆（圆相）从正上方偏左起笔、顺时针一圈（760ms），左下淡入图例 `摄像机 × 18`；
  - 主按钮悬停时墨再洇开一点，按下像笔按在纸上；路径无效时路径那块左右晃一下（只有出错才晃，M-01）。
- 窗口：760 × 480，按显示器 DPI 缩放；无边框，Windows 11 圆角 + 阴影；左侧画面和顶栏空白处可拖动；可最小化；安装中关闭按钮隐藏、Alt+F4 变成最小化；**任务栏按钮显示进度**，最小化时装好或失败会闪；安装中阻止系统睡眠。
- 键盘：回车 = 当前页主按钮（焦点在别的按钮上时由那个按钮响应）；Esc = 欢迎页取消、完成页完成；安装中不响应。
- 素材全部由 `make-ui-assets.py` 用程序生成（笔触是“很多根笔毛 + 越往后墨越少”的模型），**不许手工修图、不许换成网上的水墨素材**。

### I-25 进度如实 [定]

协调仓第 11 条：如实显示阶段，不伪造百分比。

- 百分比**只来自 7-Zip 解压器自己报告的字节数**：`xuyu-extract-progress.nsh` 在编译期把 electron-builder 的 `extractUsing7za` 换成用 `Nsis7z::ExtractWithCallback` 的版本，回调里最多每 150ms 写一次 `extractDone / extractTotal`。Wine 实测：160 MB 的包写了 9 次，只增不减。
- 解压前（检查并关闭正在运行的胥宇、卸载旧版本）是 `prepare`：**不显示数字**，只“蘸墨”；解压后复制到安装位置是 `copy`、建快捷方式和登记是 `finish`：笔画写满，文字说明正在做什么。
- **不许用定时器、估算时间或数文件夹大小去“推”进度**（撤销清单 X26）。`xuyu-extract-progress.nsh` 除了行尾带 `;XUYU` 的行，必须和 electron-builder 模板一字不差，`tools/check-extract-template.mjs` 检查；升级 electron-builder 时它会报出来，按新模板重做这份文件。
- 宿主把 `status.ini` 的变化原样转给页面，页面只负责画；页面里的“模拟宿主”只在浏览器直接打开时使用。

### I-26 装好以后 [定]

- NSIS 在 `customInstall`（安装段最后）写 `phase=done`，然后**等宿主退出**；宿主在用户点“打开胥宇”、“完成”或关窗口时写 `after.ini` 再退出；NSIS 读到 `launch` 就用 `StdUtils::ExecShellAsUser` 以普通用户身份打开胥宇（和经典完成页同一做法）。
- “打开胥宇”跟 `package.json` 的 `nsis.runAfterFinish` 走（`init.ini` 的 `canLaunch`）：为 `false` 时不显示，“完成”成为主按钮。I-05 的“先查清当初为什么设成 false”同样适用。
- 清理：宿主退出时起一个隐藏的 `cmd`，5 秒后删除会话目录（等 WebView2 子进程退干净）；删不掉的，下次运行安装程序时 `XuyuUiCleanStale` 删（Wine 实测通过）。日志 `%TEMP%\XuyuSetup-日期-时间.log` 保留，失败页“打开安装日志”打开它。

### I-27 构建 [定]

| 参考文件 | 放到 xuyu |
|---|---|
| `installer.nsh`、`installer-inkui.nsh`、`xuyu-extract-progress.nsh` | `build/` |
| `host/XuyuSetupUI.cs`、`host/app.manifest`、`host/build-host.cmd`、`host/fetch-webview2.ps1` | `scripts/installer-ui/host/` |
| `ui/*` | `scripts/installer-ui/ui/` |
| `make-ui-assets.py` | `scripts/installer-ui/` |
| `tools/check-extract-template.mjs`、`tools/protocol-test.mjs`、`tools/protocol-progress.mjs`、`tools/StubHost.cs`、`tools/FakeApp.cs` | `scripts/installer-ui/tools/` |

- `build-host.cmd` 只用 Windows 自带的 `csc.exe`（.NET Framework 4.8，**C# 5 语法**，`/warnaserror+`）编译宿主，把宿主、3 个 WebView2 文件、WebView2 许可和 `ui/` 放到 `build/installer-ui/`。这个目录是**生成的，加进 .gitignore**。
- WebView2 SDK 由 `fetch-webview2.ps1` 下载：版本 1.0.4191.47（2026-08-28 发布），SHA-512 固定，校验不过就失败。**不要把 SDK 的 dll 提交进仓库。**
- 打包命令（`npm run package:installer` 及 Preview 门禁里打 NSIS 的那一步）在 electron-builder 之前依次运行：`node scripts/installer-ui/tools/check-extract-template.mjs build/xuyu-extract-progress.nsh`（在仓库根目录运行，自动找到当前装的 electron-builder 模板，npm、pnpm 都可以）→ `scripts\installer-ui\host\build-host.cmd`。`installer-inkui.nsh` 里嵌入宿主文件的 `File` 都没有 `/nonfatal`：缺一个文件 makensis 直接失败，不会打出半套。
- 因为定义了 `customCheckAppRunning`，electron-builder 不再自动引入 `getProcessInfo.nsh` 和 `$pid`，`installer.nsh` 自己引入（已写好），否则编译失败。
- `make-ui-assets.py` 只在改页面文字或素材时由开发者手动运行（要 Python、numpy、Pillow、fontTools、brotli 和霞鹜文楷 Medium TTF，字体只用来生成子集，不进仓库），产物提交进仓库。
- 宿主运行时依赖：.NET Framework 4.8（Windows 10 1903 起自带）+ WebView2 运行时（Windows 11 自带，Windows 10 绝大多数已经通过系统更新装上）。缺一个就自动走经典向导，不弹错误。
