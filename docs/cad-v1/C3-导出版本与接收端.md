# C3 导出版本与接收端（CAD-09 至 12）

**为什么**：现在一律导出 DWG 2018。对方用老版本 CAD 就打不开。而且“生成了文件”不等于“对方能打开、能改”。

**CAD-09 导出版本跟着原图**（界面类）
- 原图是 2007、2010、2013、2018 → 导出同一版本。原图是 2000、2004 → 导出 2007，并在导出窗口说明原因：2007 起中文才是统一编码，老格式在别人电脑上容易乱码。
- 导出窗口显示“导出为 DWG 2013（和原图一样）”，旁边可以改成 2007、2010、2013、2018。
- 保真检查里的“对照组”（原图只转换、不加东西）也要用同一个版本，不然比的不是一回事。

**CAD-10 图层**
- 新导出的东西分 5 层：`XUYU_DEVICE` 设备、`XUYU_LABEL` 编号和标签、`XUYU_ARROW` 箭头和线、`XUYU_NOTE` 说明、矩形、测量、`XUYU_SUMMARY` 统计和图例。
- 以前导出的两层文件（`XUYU_DEVICES / XUYU_ANNOTATIONS`）照样能读、能改；再导出时改用新图层。
- 原图里已有同名图层：不改它的设置；被锁定、冻结或关闭时按现有规则提示。

**CAD-11 AutoCAD 2023 自动核验**：写 `scripts/cad-verify-autocad.mjs`，用 accoreconsole 处理导出文件的副本：
1. 打开，跑 AUDIT（只报告，不修）；按图层数胥宇对象，数量要和导出时一样。
2. 改一个设备编号、移动一个设备、改一段文字，另存。
3. 胥宇再打开另存的文件：改动按现有“外部 CAD 修改”规则识别出来，不丢、不重复。
4. 用“DWG To PDF”打印出 PDF，查 PDF 里嵌入的字体：胥宇写的字必须是微软雅黑，不能被替换。被替换的话，在文字样式里补上 TrueType 字体名（AutoCAD 认这个）；还不行就停下报告。
- 测试图纸的 4 个版本都要跑，样本导出也要跑。AutoCAD 不存在时，脚本要明确说“跳过：本机没有 AutoCAD 2023”，不能当作通过。

**CAD-12 浩辰 2023**：先试能不能自动化。遇到激活或登录窗口就放弃自动化，改成给用户的 3 步手动核验：
1. 用浩辰打开 `……\导出\S03-胥宇.dwg`
2. 看：设备、编号、文字都在，中文不是问号或方块；按图层能单独关掉胥宇的东西
3. 双击一个编号改成 `TEST`，保存；回胥宇打开这个文件，能看到 `TEST`
- 手动核验攒到卡结束再一起给用户。

**验收**：门禁全绿；AutoCAD 核验脚本在 4 个版本的测试图纸和至少 5 张样本上通过；CAD-09 有 e2e（导出窗口显示的版本、改版本后导出的文件头版本对得上）。

**报告里写**：各版本核验结果表；字体有没有被替换；给用户的浩辰手动核验步骤。
