## F1 今天清单、完成的判定、完成并下一份

### B-01 “今天”清单只放今天的，旧的单独一组

- **现在**：清单把所有有恢复记录、没标完成的图纸都算进“今天”，不看日期（`src/renderer/App.tsx:6351-6356`）；已完成的恢复记录被直接跳过（:6355）；顺序是先旧记录、再打开的、再异常（:6351-6371），没排序。
- **要做到**：
  - 分组逻辑写成纯函数，放新文件 `src/core/today-queue.ts`，App 只负责渲染。
  - **今天**：本次运行打开或导入过的，加上更新时间或恢复记录保存时间是今天（本地日期）的。按加入的先后排。**已完成的也留在这一组**，关掉文件后也不消失，行上打“已完成”标记。
  - **之前未完成（N 份）**：更早的、没完成也没导出过当前版本的，放在下面这一组，默认折叠。点开能照常打开和恢复。
  - 更早的、已完成或已导出的不再出现。
  - 异常照旧单独标出，规则不变。
- **怎么证明**：单元测试覆盖分组和排序（今天打开 / 今天保存 / 昨天未完成 / 昨天已导出 / 今天已完成后关闭）；e2e 用夹具造这几类图纸，检查两组的内容、顺序、折叠；截图。

### B-02 导出了就算完成

- **现在**：只有“完成并下一份”写的 `workflowStatus === 'completed'` 才算完成（`App.tsx:6375`），只导出不算。
- **要做到**：清单里“完成”的判定 = `workflowStatus === 'completed'`，**或者**当前版本已经导出（`projectHasCurrentCustomerExport`，`src/core/export-status.ts:26`）。导出后又改了，就退回未完成，行上标“改过，未重新导出”。只改清单和统计的判定，导出时**不写** `workflowStatus`，不动方案跟随（`projectSchemeFrozen`）的规则。这个判定也写进 `today-queue.ts`，B-03、B-04 用同一个函数。
- **怎么证明**：单元测试（导出未改 → 完成；导出后改一笔 → 未完成且带标记；只点完成 → 完成）；e2e：导出一份，它在清单里变成已完成，再改一笔回到未完成并出现标记。

### B-03 两个数字一致，批量导出不重复导

- **现在**：顶部“已完成 N”只数 `workflowStatus === 'completed'`；按钮“批量导出已完成（N）”用 `completedProjects.length || legacyDrawableProjects.length`（`App.tsx:3053-3063`），没有已完成的就拿“从没标过状态的旧图纸”凑数；批量导出的候选也是这套（`App.tsx:3544` 起）。
- **要做到**：两处都用 B-02 的同一个判定，两个数必须相等。去掉 `legacyDrawableProjects` 兜底。批量导出时，当前版本已经导出过的图纸跳过，结果里写“K 份已是最新，跳过”。数字是 0 时按钮不可用，点了用现有的“不可用说明”提示原因。
- **怎么证明**：e2e：1 份已导出 + 1 份只点了完成 + 1 份旧的没标状态 → 两处都是 2；批量导出只导那份没导过的，结果写“1 份已是最新，跳过”。

### B-04 完成并下一份：只在今天里找，跳过同一个 PDF

- **现在**：打开的图纸里找不到下一份时，会去恢复记录里捡一份“没完成、没打开”的打开（`App.tsx:3141-3159`）。只排除了当前工程 id，没排除同一个源 PDF，用户就被带到了同一张 PDF 的旧记录上（Codex 已在用户电脑上复现）。
- **要做到**：
  - 下一份只在 B-01 的“今天”组里找：从当前这份往后，绕回开头，跳过已完成（B-02 的判定）、异常，以及和刚完成这份**同一个源 PDF**（`source.sha256` 相同，或 `source.sourceId` 相同）的所有记录。
  - 找不到就留在当前图纸，提示“今天的都做完了”。
  - 删掉去恢复记录里自动捡一份的那段，“之前未完成”只能手动打开。
- **怎么证明**：e2e 复现用户的步骤：今天只开着一张，同一张 PDF 还有一份旧的未完成恢复记录；点“完成并下一份” → 不打开旧记录，停在当前并提示；今天有另一张未完成的 → 切到那张。

### B-05 已完成的图纸重新应用方案

- **现在**：已完成就冻结，同一方案不再应用，哪怕没导出过，提示却写“此工作已导出，保留交付时的方案”（`src/core/drawing-schemes.ts:52`、`App.tsx:1844-1845`）。
- **要做到**：冻结规则不变。提示分两种：
  - 导出过：照旧“此工作已导出，保留交付时的方案”；
  - 只点了完成、没导出：“此图纸已完成，保留完成时的方案”，提示里带一个“解除完成并重新应用”按钮。点了先确认，确认后先解除完成（复用现有 `uncompleteCurrent`，`App.tsx:3272`），再按正常流程应用方案。
- **怎么证明**：e2e 两种情况各走一遍：导出过的提示不变；只完成的点按钮、确认后方案应用上了，清单里回到未完成。

### B-06 同一个 PDF 有多份记录时分得清

- **现在**：用户电脑上同一张 PDF 有两份记录（Codex 查到的 5a953537… 和 405c7a18…），清单里名字一样，分不出哪份是哪份。
- **要做到**：
  - 清单里同一个源 PDF 出现不止一份时，这几行都多显示一行小字：更新时间、点位数、方案名。
  - 从“之前未完成”打开一份记录时，如果同一个 PDF 今天已经有别的记录（打开着、或今天完成过），先弹确认，列出两份的更新时间、点位数、方案，用户选了再开。
- **怎么证明**：e2e：同一 PDF 一份今天已完成、一份昨天未完成，行上有区分信息；打开昨天那份时出现确认，取消就不打开。

## F2 切回文件、翻页

### B-07 切回一个文件时回到上次看的那页

- **现在**：`activateDocument` 每次都切到第一页（`App.tsx:1250-1252`）。Codex 复现了：图例放在第 2 页，切到别的文件再切回来，显示第 1 页，图例按 `pageId` 被过滤（`FloorPlanCanvas.tsx:879`），看着像图例没了。
- **要做到**：在内存里按文件记住上次看的页（不存盘）。切回时回到那页；那页被删了就回第一个没删的页。
- **怎么证明**：e2e 复现用户的步骤：在第 2 页按方案放图例（设备汇总 → 全部放到图上），切到另一个文件再切回 → 停在第 2 页，图例节点可见。再加一条：图例在第 1 页，同样操作后可见（用户那份的情况）。用户说过“切回来看不到图例但导出正常”，这两条都过了以后，在报告里写清楚：用户那份如果仍复现，需要用户提供什么信息。

### B-08 翻页不闪、看过的页秒切

- **现在**：换页时先清空画布、进入“加载中”（`FloorPlanCanvas.tsx:629-633`），固定等 110ms 才去取图（:634、:659），哪怕这页在缓存里；缓存键带渲染倍率（`src/renderer/pdf-raster-cache.ts:14`），适配窗口时倍率一变就取不到；不提前准备相邻页。
- **要做到**：
  1. 换页时旧页面保持显示，新页面准备好再一次性换上；只有超过约 300ms 还没好，才显示加载提示。
  2. 缓存里已有的页面立即显示，不等 110ms。
  3. 渲染倍率按档位取整，适配窗口带来的小变化不让缓存失效；空闲时在后台提前准备前后各一页，总量仍受现有 192MB 上限约束。
  - 从别的模块切回绘图会重新加载，这一条（A2 的 b）本轮不做。
- **怎么证明**：e2e 两页夹具：第 1 页 → 第 2 页 → 第 1 页，第二次回到第 1 页时 `data-render-state` 不经过 `rendering`；新页面没准备好的那一刻旧页面仍在（截图）；单元测试覆盖倍率取整。

## F3 补上没接的小动效（v4 规格 M-04 原样，不新造）

### B-09 放监控点位：落点涟漪 + 弹入

- **现在**：`ripple()`（`src/renderer/feedback/index.ts:83`）全仓没人调用；弹入只对汇总图例做（`FloorPlanCanvas.tsx:895-905`）。
- **要做到**：放监控点位时，落点处一圈涟漪，点位弹入。画在叠加层，不进导出。
- **怎么证明**：e2e 放一个点位，叠加层出现 `.fx-ripple` 和该点位的 `.fx-drop-in`；导出的 PDF 里没有；打开减少动效后不出现。

### B-10 数量变化：数字滑入 + “+1”

- **现在**：只有批量队列“已完成 N”带差值气泡（`BatchQueuePanel.tsx:193`）；设备浮窗“已放 N”只滑数字（`DevicePanel.tsx:33`）；汇总清单数量只有整行高亮（`SummaryList.tsx:198`）。
- **要做到**：设备浮窗“已放 N”和汇总清单的数量都用 `animateNumber(..., { showDelta: true })`：数字滑入，旁边飘“+1”（减少时“−1”）。
- **怎么证明**：e2e 放一个点位，设备浮窗该行出现 `.fx-delta` 文本“+1”；汇总清单减一，出现“−1”；减少动效下不出现。

### B-11 增删行、拖动排序时其余项平滑归位

- **现在**：`flip()` 只用在今天清单筛选和导出记录筛选（`App.tsx:6384`、`ExportLog.tsx:82`）。
- **要做到**：汇总清单增删行、页面列表拖动排序（`PagePanel.tsx`，`page.move`）也用 `flip()`。
- **怎么证明**：e2e 汇总清单加一行，其余行的位置变化走了过渡（检查 `getAnimations()`）；减少动效下没有。
