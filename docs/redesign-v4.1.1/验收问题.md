## A1 资料 → 文件：“今天”清单

**现象**（截图：“今天 18 份 · 已完成 0”，旁边按钮却是“批量导出已完成（1）”，列表里大多是 10 月之前的图纸，今天打开的排在下面）

1. 用户认为导出 PDF 就算做完了，但清单里导出过的图纸仍是未完成。
2. 以前没点过“完成”的图纸一直留在“今天”里。
3. 今天打开的图纸不在最上面。
4. 顶部“已完成 0”和按钮“批量导出已完成（1）”数字不一致。

**原因**

- 完成只认 `workflowStatus === 'completed'`，只有“完成并下一份”会写它（`src/renderer/App.tsx:6375`）。导出不会。
- “今天”的来源（`App.tsx:6351-6356`）把所有有恢复记录、且没标完成 / 异常的图纸都算进来，不看日期。
- 列表按插入顺序：先放旧恢复记录，再放今天打开的，再放异常（`App.tsx:6351-6371`），没有排序。
- 按钮数 `quickBatchCount = completedProjects.length || legacyDrawableProjects.length`（`App.tsx:3063`）：没有已完成图纸时，会把从没标过状态、有点位的旧图纸也算进去；顶部数字只数已完成。

**改法（用户已同意）**

1. **导出就算完成**：图纸已导出，而且导出后没再改过（沿用 `projectHasCurrentCustomerExport`，`src/core/export-status.ts:26`），在清单里算“已完成”。导出后又改了，退回“未完成”，行上标“改过，未重新导出”。“完成并下一份”按钮保留，行为不变。注意：这里只改“清单里怎么算完成”，要不要同时写入 `workflowStatus`，写修改单时再核对它对方案跟随（`projectSchemeFrozen`）、批量导出、恢复的影响；不新增保存字段。
2. **“今天”只放今天的**：今天打开、导入或保存过的图纸放在上面，按加入的先后排（“完成并下一份”往下走）。
3. **之前没做完的单独一组**：以前的、没完成也没导出的图纸，放在下面一组“之前未完成（N 份）”，默认折叠，不删、不丢，点开照常能打开和恢复。以前已经导出过的不再出现在这里。
4. **数字统一**：顶部“已完成 N”和“批量导出已完成（N）”按同一个标准数，两个数必须相等；没有已完成的图纸时按钮显示 0 或不可用，不再拿旧图纸凑数。

**怎么证明（写修改单时细化）**：e2e 用夹具造三类图纸——今天导出过的、今天没导出的、前几天没完成的（带恢复记录）——检查分组、顺序、两个数字；导出后改一笔，回到未完成并带标记；“之前未完成”里的图纸点开能恢复。

## A2 切换页面每次都重新加载

**现象**：用户反馈“切换页面为啥都要重加载”，确认是**绘图里同一个文件翻页**（下面的 (a)）。(b) 一并记下，改不改写修改单时再定：
- (a) 绘图里翻页（工具栏“第 1/2 页”、资料 → 页面里点缩略图）；
- (b) 顶部模块切换（绘图 → 工作台 / 配置 → 再回绘图）。

**原因**

- (a) 换页时画布先清空、进入“加载中”（`src/renderer/components/FloorPlanCanvas.tsx:629-633`），再固定等 110ms 才去取图（:634、:659），哪怕这一页早就画过、在缓存里（`src/renderer/pdf-raster-cache.ts`，192MB 的 LRU）。缓存键带着渲染倍率（:14），换页后适配窗口的倍率一变就取不到，只能整页重画；也不会提前准备相邻页。
- (b) 各模块是整棵界面直接替换（`src/renderer/App.tsx:6133-6200` 按 `workspace` 提前 return），离开绘图时画布整个卸载，回来重新挂载，又从“加载中”开始。

**改法（建议，待用户确认）**

1. 换页时，旧页面保持显示，新页面准备好再一次性换上；不出现空白和加载遮罩，除非新页面超过约 300ms 还没好。
2. 缓存里已有的页面立即显示，不再等 110ms。
3. 倍率按档位取整，适配窗口带来的小变化不让缓存失效；空闲时在后台提前准备前后各一页。
4. 从别的模块回到绘图：直接显示离开时的画面，不重新走加载。优先用“回来时命中缓存就直接显示”这种小改法；要让绘图界面在切模块时保持挂载属于结构改动，写修改单时再评估，不顺带做。

**怎么证明**：e2e 用两页夹具，第 1 页 → 第 2 页 → 第 1 页，第二次回到第 1 页时 `data-render-state` 不经过 `rendering`；切到工作台再回绘图，同样不经过 `rendering`；新页面没准备好时旧页面仍在显示（截图）。

## A4 水墨主题不够出彩

**现象**：用户觉得水墨主题“设计得还不够出彩，很多能水墨的地方都没有”。

**核对结果**：软件里的 `src/renderer/themes/inkwash.css` 和 Claude 当初给的参考 `docs/redesign-v4/reference/themes/inkwash.css` 逐字相同，Codex 照做了。问题在设计本身：水墨只换了一套颜色、铺了宣纸纹理、把主按钮换成毛笔刷块（`swipe-ink.png` / `swipe-paper.png`），其余控件和其他风格长得一样。

**可以加水墨味的地方（候选，出设计稿时和用户逐项确认）**

1. 模块标签当前项：下划线换成一笔带飞白的毛笔横。
2. 页面和浮窗标题：用楷体（霞鹜文楷，开源许可，安装器已经在用）。
3. 选中的行和卡片：淡墨晕染底，代替纯色块。
4. “已完成”、“默认”这类标记：朱红小印章。
5. 加载中：墨滴晕开，代替转圈。
6. 空状态（“打开图纸”页、没有方案时）：一幅很淡的远山水墨。
7. 分隔线：枯笔飞白线。
8. 开关、分段按钮的滑块：一颗墨点。
9. 切换模块和主题：墨晕扩散的过渡（现成的刷块图可以复用）。
10. 画布四周：宣纸纹理加极淡的墨渍角花。
11. 提示气泡、滚动条：纸笺样式、细墨线。

**约束**：只在“水墨”风格下生效，其他 9 套不变；图纸内容和导出的 PDF 不受影响；白天、夜间、护眼三种模式都要过对比度检查；动效遵守“减少动效”；不新增保存字段。

## A5 完成并下一份后点位和图例丢失（优先）

**用户操作**：
1. 一张单页图纸画完，点“完成并下一份”；
2. 打开的还是这张图，但点位没了；
3. 放一个点位，再点“完成并下一份”；
4. 结果：“已完成”里这张图只有一份；方案里的图例全没了；重新应用方案也回不来。

**代码里看到的可能原因（未复现，要 Codex 在用户电脑上确认）**

1. **“下一份”可能是同一个文件的旧副本**：打开的图纸里没有下一份时，会去恢复记录里找一份“没完成、没打开”的接着开（`src/renderer/App.tsx:3149` 起，调用 `restoreRecoveryProjects`）。这和 A1 是同一个根：以前没点过完成的旧恢复记录都算“待处理”，其中很可能就有这张 PDF 之前的旧副本，所以看上去“还是这张图，点位没了”。
2. **“已完成只剩一份”**：第一份完成后不在打开的列表里时，“今天”清单把已完成的恢复记录直接跳过（`App.tsx:6351-6356` 的 `workflowStatus === 'completed'` → continue），所以界面上只看得到后来那份。第一份应该还在恢复记录里，需要确认。
3. **重新应用方案没反应**：已完成或导出过的图纸按设计不再跟随方案（`App.tsx:1844-1845`，提示“此工作已导出，保留交付时的方案”）。旧副本如果以前导出过，一打开就是“冻结”状态。
4. **图例为什么全没了**：**用户补充（2026-10-19）：是显示问题，数据没丢**。按方案放完图例，点到下一个文件再点回来，画布上看不到图例，但导出的 PDF 里图例正常。待 Codex 复现，Claude 看代码想到的几个方向：
   - 回来时显示的不是图例所在那一页（图例的 `pageId` 和当前页不一致；导出是按所有页导，所以导出正常）；
   - 切走时 `scheduleSessionCleanup` 清了共享图片缓存（`App.tsx:1225-1234` → `shared-image-cache.ts:58` `clearReleasedSharedImages`），切回来图例的图片没重新拿到；
   - 切回来时图例对象没进画布的渲染列表（`FloorPlanCanvas.tsx:879` 按 `pageId` 过滤）。

**处理**：先只读查清楚、不改代码（发给 Codex 的话见对话记录），确认第一份完成的图纸还在、在哪；再定修法。初步修法方向：
- “完成并下一份”只在本次打开 / 今天的清单里找下一份；没有就停在当前图纸并提示“今天的都做完了”，不再去翻旧恢复记录；
- 同一个 PDF 有多份工作时，打开前明确提示是哪一份（更新时间、点位数），不再悄悄打开旧副本；
- 已完成的图纸要能在清单里找到（并入 A1 的分组规则）；
- 图例丢失的原因查清后单独修，并加回归测试。

**Codex 只读核查结果（2026-10-20，用户电脑，时间 UTC+7）**

- **第一份完整还在**：9 个点位、1 个图例，没有被覆盖；工程文件和两份备份哈希一致，导出归档也在。

**修法（Claude 建议，待用户确认）**

1. “完成并下一份”只在今天的清单（A1 的分组）里找下一份，并且跳过和刚完成那份**同一个源 PDF** 的所有记录；找不到就留在当前图纸，提示“今天的都做完了”。不再自动打开旧恢复记录，旧的在“之前未完成”里手动开（A1）。
2. 已完成的图纸关掉后，仍留在今天清单的“已完成”里（并入 A1）。
3. 切回一个文件时回到上次看的那一页，不再强制第 1 页。这条本身就该改，也可能就是“切回来看不到图例”的原因；改完请用户再试一次，不行再查。
4. 已完成但没导出的图纸重新应用方案：提示改准确（“已完成，保留完成时的方案”），并给一个“解除完成并重新应用”的按钮，点了先确认。导出过的照旧冻结，提示保持“已导出，保留交付时的方案”。

## A10 拖回已导出的成品再改，结果放进了“存放”（用户 2026-10-23）

- **用户设置**：存放 = `E:\OneDrive\图纸\临时存放`，完成和导出成果根目录 = `E:\OneDrive\图纸\临时完成`。存放里出现了 “TSV_TSC_CCTV (2).pdf”“07102026 Design Concpet_Star Box_CCTV (2).pdf”“TPV_KLM_CCTV (2).pdf”，时间都是 10/23 9:55。
- **Claude 在 `b6ee2f5` 上完整复现了这条链**：
  1. 把成品从“临时完成”拖进软件。软件把所有不在存放里的拖入文件都先复制进存放，名字撞了就加 “(2)”。成品被当成了新原件。
  2. 原工作已交付，软件另开“新修订”。新修订把刚打开的那份副本当成“上次导出位置”。
  3. 再导出，就写进了存放。工具栏却一直写着“成果目录：临时完成”。
- 用“打开图纸”按钮从完成文件夹打开不会这样，只有拖入会。
- **用户那几个 “(2)” 文件**：原件（不带 (2) 的）没动过。带 (2) 的是拖进来时复制的成品；如果导出时选了“覆盖原文件”，它现在就是改完的那一版。先别删，要交付就用它，改个名放到完成文件夹即可。
- **修法**：v4.1.1 F5 的 B-19。拖入时成品原地打开、不复制；重新导出回到成品所在文件夹，永远不写进存放；工具栏显示真实的导出位置。
