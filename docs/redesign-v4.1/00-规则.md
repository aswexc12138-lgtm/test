# 00 · v4.1 规则（Codex 先读这一页）

v4.1 只做一件事：把**方案编辑器、配置中心、快捷键、取色、绘图左侧联动**按设计稿改好。v4 的 `docs/redesign-v4/00-硬约束.md` 和 `07-审计结论与返工.md` 仍然有效；和本页冲突时以本页为准；和协调仓 `AGENTS.md` 冲突时以 AGENTS 为准，写进报告。

## 一、先读什么

1. 本页；
2. `01-规格.md`：全部编号，每条写了现在在哪、要做到什么、怎么证明；
3. `设计稿/截图/`：15 张图。设计稿源文件是 `设计稿/*.dc.html`，样式和动画参数可以直接从里面抄；
4. `界面问题清单.md` 第六节《原有功能对照表》：**表里每一行都要在新界面里找得到。表里没有的，不许删。**

## 二、顺序和节奏

- 顺序：**Q1 → Q2 → Q3 → Q4 → Q5 → Q6 → Q7 → 最终**。一口气做完，阶段之间不等用户，最后一次性验收。
- 每个阶段开工：用不超过 10 行复述本阶段要做的编号和计划，写进阶段报告开头，然后直接做。
- 每个阶段只改 `phase-scope.json` 里本阶段 `allow` 的文件。要改范围外的文件，同时满足下面五条就不用等用户：不碰 CAD；不改已保存数据的格式或字段含义（第五节列出的除外）；不删、不移动用户文件；不改默认快捷键和版本号；改动只为本阶段编号服务。直接在 `phase-scope.json` 本阶段加上文件和一句 `scopeRevision` 理由，单独一次 docs 提交，然后继续。最终报告单列这些修订。
- 规格写错或说不清：选和现有行为一致、改动最小的那种理解，写进阶段报告，接着做。
- 开发中只跑相关的单测和单个 e2e；确信改完了才跑一次完整 `run-gates`，中途任何一项失败就停掉，修好后从头再跑。
- 每个阶段收工跑一条命令，**没过不许进下一阶段**：

```bash
node docs/redesign-v4/reference/run-gates.mjs --phase QX --base <本阶段起始提交> \
  --scope docs/redesign-v4.1/phase-scope.json --trace docs/redesign-v4.1/traceability.json \
  --out docs/redesign-v4.1/reports/gates --wiring-base <导入提交> --e2e <本阶段新增或改动的 e2e 文件…>
```

  `<导入提交>` 是导入本包的那次提交，也是 Q1 的起始提交。阶段 e2e 跑 1 遍，最终连跑 3 遍（`--repeat 3`）。
- 每个阶段：报告写 `docs/redesign-v4.1/reports/QX-报告.md`（门禁一节原样贴 `summary.md`），更新 `reports/进度.md`，单独提交并同步。

## 三、什么叫“做完”

一个编号标 `done`，四样都要有：

1. **软件里看得到、用得到**：从入口一路接上，`wiring-check` 能证明。
2. **行为测试**：测试名带编号（例如 `'V-01 数字框滚轮加一、Shift 加十'`），调用软件实际在用的函数或组件。读源码查字符串的测试不算（diff-guard G9）。
3. **界面类编号要有 e2e**：后台模式 `CCTV_E2E_HEADLESS=1` 加隔离的 `CCTV_E2E_USER_DATA`，照现有 `tests/e2e/` 的写法，在软件里真的点一遍。`phase-scope.json` 每个阶段的 `ui` 列表就是界面类编号，`trace-check` 会查。
4. **截图**：用同一个 e2e 测试截，放 `docs/redesign-v4.1/reports/screenshots/QX/`，白天和一套夜间各一张。报告里把你的截图和 `设计稿/截图/` 里对应那张并排列出来。用不能看图的模型时，截图标 `UNREVIEWED`，不许写“已目视核对”。

不许用 `partial` 往下走。不许删断言、放宽阈值、关检查来过关。

## 四、写法

- **文字**：用户能看到的字用设计稿里的原文；设计稿里没有的，沿用软件现在的文字。不另造文案。
- **颜色**：界面颜色只用主题变量 `var(--…)`（G4）。设计稿里写死的颜色只是示意，换成对应的主题变量；夜间主题下也要看得清。取色浮层里的图纸色是数据，放 `src/core/` 的常量里，不受 G4 限制。
- **动效**：沿用 v4 的三档（交互 ≤ 320ms，`fx-` 余晖 ≤ 1200ms）。**例外只有一个**：V-20 左侧联动动画归 `fx-` 档，总长 1200ms，用 Web Animations API 播放，允许改面板高度（平时不许对布局属性做动画）。所有动画在“减少动效”打开时不播，直接到结果。
- **控件**：数字框和取色用 Q1 做的组件；分段按钮、开关、`?` 提示做成公共组件放 `src/renderer/components/ui/`，第一次用到时做，后面复用。不在页面里各写一份。绘图里的弹窗和方案页用同一套组件，只是作用范围不同（本文件或整个方案）。
- **快捷键**：现有默认键一个都不改；用户改过的键永远不被覆盖；命令名和分组以软件现在的命令注册表为准，设计稿里的命令列表只是示意布局。

## 五、数据（v4 硬约束 R8 照旧）

- 不删字段、不改已有字段的含义；新字段一律可选。
- 本轮只有这几处数据变化，都在 `01-规格.md` 里写清了字段和迁移：V-07（大小写并进前缀）、V-13（汇总组合，旧的“固定汇总设备”和本机“常用设备组合”迁进来；V-24 写图纸的 `summaryComboId`）。取色的“最近使用”存 `localStorage`，不算保存字段。除此之外要动保存下来的字段，停下来问。
- 每个迁移都要有测试：旧数据读入 → 迁移 → 保存 → 再读入，**图上内容和导出结果不变**；第二次读入不再迁移。

## 六、什么时候停下来问用户

只有这四种，其他问题选改动最小的做法，写进报告，接着做：

1. 要删除或移动用户的文件；
2. 要动第五节以外的保存字段；
3. 会丢数据或弄坏工程的问题，修了两次还没好；
4. 某个编号确实做不了（技术上不可行，或者缺用户提供的东西）。

## 七、这一轮不做

- **品牌标识**（v4 G-02）：用户还没给素材，标题栏左边继续用现有图标；
- **资料整理、绩效页面的布局**（问题清单 M1、M2）：没有设计稿，下一轮再做；
- **CAD**：单独一个版本；
- 绘图里除了 V-18 到 V-26 以外的东西：工具栏、画布、右侧属性和汇总清单的其他部分、状态栏，都保持现状；
- 设计稿里画了、但要加新字段或新功能的几处：方案卡片“复制一份”、文件重名时的可选项、保留矢量底图的开关。这一轮照现状显示。
